**`data-table`** is a listing kit built on TanStack Table. It bundles toolbar search, column filters, sorting, pagination, row selection, bulk actions, optional URL sync (`nuqs`), and persisted column preferences.

## When to use it

- Admin catalogs, IAM lists, audit logs, and any screen with **search + filters + paging**
- Flows that need **row selection** and a **bulk action bar** (export, delete, assign)
- Listings that should **share state in the URL** (page, limit, sort, filters) for refresh-safe bookmarks

Skip URL sync (`syncUrl={false}`) for embedded tables on detail pages or docs previews.

## Usage

### Minimal table

<ComponentPreview
  code={`"use client"

import type { ColumnDef } from "data-table"
import { DataTable, DataTableColumnHeader, commonColumns } from "data-table"

const columns: ColumnDef<Person>[] = [
  ...commonColumns.selectColumn<Person>(),
  {
    accessorKey: "name",
    header: ({ column }) => <DataTableColumnHeader column={column} title="Name" />,
  },
  {
    accessorKey: "email",
    header: ({ column }) => <DataTableColumnHeader column={column} title="Email" />,
  },
]

<DataTable
  tableId="people"
  columns={columns}
  data={rows}
  displayKey="name"
  selectionKey={(row) => row.id}
  syncUrl={false}
/>`}>
  <TableBasicExample />
</ComponentPreview>

### Columns

- Use **`DataTableColumnHeader`** for sortable labels.
- Import **`commonColumns.selectColumn()`** for the selection checkbox column.
- Declare filters in column `meta.filter` or pass **`filterDefinitions`** for toolbar-only filters.
- Pass **`filterOptions`** from the server for distinct facet values (not derived from the current page rows).

### URL sync

When `syncUrl={true}` (default):

- `page`, `limit`, sort, search, and filter keys are written to the query string.
- Client listings read params via `useEffectiveSearchParams` inside the kit.
- Set `urlServerRefresh={true}` on server-driven pages so RSC refetches after shallow updates.

### Server-driven pagination

Pass **`pageCount`** and **`rowCount`** when data is paged on the server. The kit uses manual pagination; your loader fetches the current slice.

```tsx
<DataTable
  tableId="accounts"
  columns={columns}
  data={pageRows}
  rowCount={total}
  pageCount={Math.ceil(total / limit)}
  displayKey="name"
  syncUrl={true}
  urlServerRefresh={true}
/>
```

### Embedded table

```tsx
<DataTable
  tableId="audit-on-detail"
  columns={columns}
  data={rows}
  displayKey="action"
  syncUrl={false}
  hideViewOptions
/>
```

## Gotchas

<DocsCallout title="filterOptions scope">
  Distinct filter values must come from the **full dataset** (or server facets), not from `data` on the current page—otherwise options shrink as users paginate.
</DocsCallout>

<DocsCallout title="Nuqs adapter">
  Without `DataTableNuqsAdapter`, URL sync hooks throw at runtime. Add the adapter before any `syncUrl={true}` table mounts.
</DocsCallout>

<DocsCallout variant="warning" title="Suspense">
  `DataTable` is wrapped in `Suspense` for search params. Provide a fallback or parent Suspense boundary on App Router pages.
</DocsCallout>
