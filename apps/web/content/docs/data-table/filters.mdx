Filters can be declared on column `meta` or supplied through `filterDefinitions` for toolbar-only filters.

<PlaygroundLink href="/examples/table/filters">DataTable — filters</PlaygroundLink>

## Installation

```tsx
import {
  FilterPanelContent,
  FilterSearchPanel,
  FilterSortPanel,
  filterRenderers,
  resolveFilterDefinitions,
} from "data-table/filter"
```

## Filter options

Pass distinct option lists keyed by filter id:

```tsx
<DataTable
  filterOptions={{
    status: statusOptions,
  }}
  // ...
/>
```

Options should come from the **full** dataset (unscoped distinct values), not only the current page.

## Definitions

`DataTableFilterDefinition` describes kind, labels, and behavior when columns do not embed filter meta. Use `resolveFilterDefinitions` helpers when composing dynamic tables.

## Persistence

`filter-persistence` utilities (under `data-table/filter`) read/write stored filter preferences where enabled.

## Notes

- URL keys are derived via `columnSearchParamKey` and friends—keep keys stable when renaming columns.
- Pair with [FieldKit](/docs/form/field-kit) when building standalone filter forms outside the table.
