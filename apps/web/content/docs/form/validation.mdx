FormKit validates with Zod on submit (and on change via React Hook Form `mode: "onChange"`). Messages surface on `Field` components from the shared `ui` field primitives.

<PlaygroundLink href="/examples/form/validation">FormKit — validation</PlaygroundLink>

## Installation

```tsx
import { FormKit, applyServerErrors, focusFirstError } from "form"
import { z } from "zod"
```

## Client rules

Define constraints in the schema passed to FormKit:

```tsx
const schema = z.object({
  email: z.string().email("Enter a valid email"),
  age: z.coerce.number().min(18, "Must be 18 or older"),
})
```

Use `translateError` on FormKit when message strings are i18n keys rather than literal copy.

## After submit

On validation failure, FormKit focuses the first invalid field (`shouldFocusError` on the underlying form).

## Server errors

Map API responses to field errors:

```tsx
onSubmit={async (values) => {
  try {
    await save(values)
  } catch (error) {
    applyServerErrors(form, mapUnknownServerError(error))
  }
}}
```

Or provide `mapServerError` on FormKit to integrate with your API error shape (`MapServerErrorResult`).

## Utilities

| Export | Role |
| --- | --- |
| `resolveFieldErrorMessage` | Normalize error objects for display |
| `mapUnknownServerError` | Best-effort parse of unknown errors |
| `focusFirstError` | Focus first RHF error manually |

## Notes

- Zod **4** schemas are supported via `@hookform/resolvers` 5.x.
- For async server validation, set field errors in `onSubmit` and avoid throwing unhandled rejections so `isPending` can reset.
