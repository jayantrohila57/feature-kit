The **`layout`** shell exports build on `ui` `Shell` and `Sidebar` primitives. Use them when a route needs persistent app chrome; keep business logic and data fetching in the host app.

## Composition model

```text
DashboardShell
├── SidebarProvider (from ui)
│   ├── DashboardHeader → Breadcrumbs + actions (theme, etc.)
│   ├── Sidebar → brand, DashboardSidebarNav, DashboardAccountMenu
│   └── Shell.Main → your page (tables, forms, settings)
TopNavShell → header + optional horizontal nav (no sidebar)
AuthSplitShell → auth column + marketing aside
SettingsLayout → secondary nav inside main
```

### `TopNavShell`, `SettingsLayout`, `AuthSplitShell`, `ContentPageHeader`

| Component | Role |
| --- | --- |
| `TopNavShell` | Header + main without sidebar |
| `SettingsLayout` | Title + vertical section nav + panel |
| `AuthSplitShell` | Two-column auth/marketing |
| `ContentPageHeader` | Page title, description, actions row |
| `DashboardSidebarNavSkeleton` | Sidebar placeholder groups |
