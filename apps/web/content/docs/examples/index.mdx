## How to read an example

Each preview is a docs-site client example. Check the linked source component for complete imports and host-app wiring. The examples use local demo handlers; replace those handlers with your API or mutation and keep server authorization and validation in the host application.

Recommended progression:

1. Start with the smallest example for the kit.
2. Add one state concern, such as loading, empty, validation, or URL synchronization.
3. Combine kits in a screen workflow: breadcrumbs and form sections around a form, or table actions with confirmation.

## Cross-kit workflows

- **User management:** [breadcrumbs](/docs/examples/layout/breadcrumbs) → [validation](/docs/examples/form/validation) → [bulk actions](/docs/examples/table/bulk-actions). The layout package supplies wayfinding, FormKit owns form state, and DataTable owns listing interactions.
- **Spreadsheet onboarding:** [empty states](/docs/examples/table/empty) → [basic uploader](/docs/examples/uploader/basic). Use an empty state to explain setup, then let the uploader handle template, parsing, and feedback.
- **Production listing:** [URL sync](/docs/examples/table/url-sync) → [row actions](/docs/examples/table/row-actions). Keep fetching and authorization in the host app; pass the resulting data and action callbacks into the feature components.
